Intelligence Layer & Deep Profiling

A technical deep-dive into Kursa's event-driven semantic memory architecture, detailing exact schema files, ingestion loops, context processors, and active LLM integration points.

System Overview

In previous iterations, Kursa's career intelligence worked on a simple static pipeline: it loaded the user's current structural profile (skills, experiences) directly into the LLM context to run estimations and paths. This created a major ceiling—Kursa possessed no persistent memories, could not track short-term sentiment trends, and had no way of understanding daily user activity.

The Core Mental Model Shift: Instead of simple snapshot processing, Kursa now processes a pipeline of: Event Ingestion → Context Extraction → Structural Delta Application → Semantic Memory Distillation → Target Assembler → LLM Narration.

The Architectural Blueprint

Your teammate integrated a multi-layered profiling framework divided into three distinct operational data boundaries:

Layer 1 Structural Profile
Prisma Profile and direct relational models (Skills, WorkHistory, Education). Stores long-term, hard queryable facts such as current employer, years of experience, and verified skill arrays.
Location: schema.prisma → profile.prisma
Layer 2 Episodic Log
Persistent, timestamped log of daily telemetry actions (CareerEvent). Every check-in, logged accomplishment, peer feedback, or text note is captured chronologically.
Location: schema.prisma → memory.prisma
Layer 3 Semantic Memory
Persistent distilled user facts (UserMemory). Tracks high-level patterns (like low engagement streaks or career goals) complete with confidence ratings and reference mapping to parent events.
Location: schema.prisma → memory.prisma

Prisma Database Schemas

The core intelligence schemas are kept inside packages/db/prisma/schema/models/memory.prisma. This modular layout prevents database congestion. Below are the precise schemas supporting events and distillation:

Career Event Log (Episodic)

Holds the telemetry signals generated by user check-ins or other integrations:

model CareerEvent {
  id                  String            @id @default(uuid())

  linkedWorkHistoryId String?

  occurredAt          DateTime          @default(now())

  @@index([userId, occurredAt])
  @@index([profileId, type])

Semantic Memory Model

Maintains persistent user observations derived over time by our distillation loop:

packages/db/prisma/schema/models/memory.prisma Prisma Model 
model UserMemory {
  id             String    @id @default(uuid())
  userId         String
  user           User      @relation(fields: [userId], references: [id], onDelete: Cascade)
  category       String    // e.g., "sentiment", "pattern", "skill", "goal", "contradiction"
  fact           String    // High level observation text
  confidence     Float     // Decay-supported rating between 0 and 1
  sourceEntryIds String[]  @default([]) // Provenance IDs linking back to CareerEvents
  validFrom      DateTime  @default(now())
  validUntil     DateTime? // Populated when memory becomes stale or superseded
  supersededBy   String?   // Points to the UserMemory id that replaced it
  createdAt      DateTime  @default(now())

  @@index([userId, category])
  @@map("user_memory")
}

The Event Ingestion Loop

The ingestion sequence begins when a telemetry transaction is recorded. For example, logging a career "win" sends a request to the server, routed through apps/server/src/services/events.service.ts:

apps/server/src/services/events.service.ts ingestEvent() 
export async function ingestEvent(userId: string, input: CreateCareerEventInput) {
  const profile = await resolveProfile(userId);
  const extracted = extractFromEvent(input.type, input.structured);

  // 1. Resolve entity mapping (Skills, Path, etc.)
  const links = await resolveInitialLinks(profile.id, input.type, input.structured);

  // 2. Create the CareerEvent log
  const event = await prisma.careerEvent.create({
    data: {
      userId,
      profileId: profile.id,
      type: input.type,
      source: input.source,
      body: input.body ?? null,
      structured: input.structured as never,
      sentiment: extracted.sentiment,
      linkedSkillIds: links.linkedSkillIds,
      linkedPathId: links.linkedPathId,
      linkedWorkHistoryId: links.linkedWorkHistoryId,
      occurredAt: input.occurredAt ?? new Date(),
    },
  });

  // 3. Apply profile updates automatically using a computed delta
  if (!input.skipDelta) {
    const delta = computeProfileUpdateDelta({
      id: event.id,
      type: event.type,
      body: event.body,
      structured: event.structured,
    });
    await applyProfileUpdateDelta(profile.id, delta);
  }

  // 4. Distill semantic observations immediately
  if (!input.skipDistill) {
    await runMemoryDistillation(userId, profile.id);
  }

  return toSummary(event);
}

Automatic Structural Updates (`profile-delta.ts`)

When an event is captured, the system maps it to structural changes to update the main user profile. For example, a "win" event updates the target skill usage dates and achievements:

apps/server/src/compute/profile-delta.ts computeProfileUpdateDelta() 
export function computeProfileUpdateDelta(event: CareerEventForDelta): ProfileUpdateDelta {
  const structured = event.structured as Record<string, unknown>;

  switch (event.type) {
    case "win": {
      const title = String(structured.title ?? event.body ?? "Win");
      const skillNames = Array.isArray(structured.skillNames) ? structured.skillNames : [];
      return {
        newAchievements: [
          {
            title,
            description: String(structured.body ?? "") || undefined,
            dateAchieved: new Date(),
            skillNames,
          },
        ],
        skillLastUsed: skillNames.map((name) => ({ name, date: new Date() })),
      };
    }
    case "learning": {
      const skillName = String(structured.skillName ?? "").trim();
      return {
        newLearningGoals: [{ skillName }],
        skillLastUsed: [{ name: skillName, date: new Date() }],
      };
    }
    default:
      return {};
  }
}

Memory Distillation Architecture

Distillation crunches the episodic log to extract persistent traits, operating through a hybrid deterministic and semantic LLM pipeline:

Deterministic Rules Heuristic Engine
Evaluates hard-coded metrics over the telemetry history, such as low challenge scores in weekly check-ins or theme word repetitions.
File: compute/memory.distill.ts
AI / LLM Extraction Enrichment Engine
Uses distillMemoriesWithLlm() to semantic-crunch logs, extracting detailed pattern matches and qualitative sentiment adjustments.
File: lib/ai/enrichment.extract.ts

Contradiction & Overriding Mechanism

A key capability of the memory system is managing contradictory traits. If a user states a target role of "Staff Leadership", but their check-ins show no collaborative or leadership actions, it flags a "contradiction" memory. If check-ins then shift to a collaborative nature, the system overwrites the older trait:

apps/server/src/services/memory.service.ts upsertMemoryCandidates() 
// Handles contradictions by setting validUntil and linking the new superseding memory
const contradiction = existingMemories.find(
  (m) => m.category === candidate.category && isContradiction(m.category, m.fact, candidate.fact)
);

if (contradiction) {
  const newMemory = await prisma.userMemory.create({
    data: {
      userId,
      category: candidate.category,
      fact: candidate.fact,
      confidence: candidate.confidence,
      sourceEntryIds: candidate.sourceEntryIds,
    },
  });
  
  await prisma.userMemory.update({
    where: { id: contradiction.id },
    data: { 
      validUntil: new Date(), 
      supersededBy: newMemory.id 
    },
  });
}

Confidence Decay

Memory confidence naturally decays unless refreshed by active career events: if no events matching the memory's sourceEntryIds occur within 90 days, the memory's confidence score decays by 15% (DECAY_FACTOR = 0.85).

Advisor Context Assembler

LLM prompts never interact directly with raw database layers. Instead, the backend aggregates profile stats, episodic logs, and semantic memories into a targeted payload called the AdvisorContext:

apps/server/src/lib/advisor-context.ts assembleAdvisorContext() 
export async function assembleAdvisorContext(
  userId: string,
  purpose: AdvisorPurpose,
): Promise<AdvisorContext | null> {
  const profile = await prisma.profile.findUnique({
    where: { userId },
    select: { ...PROFILE_SELECT, careerPaths: { where: { isActive: true }, take: 1 } },
  });

  if (!profile) return null;

  // Retrieve relevant time windows (e.g., 28 days for active users, 84 days for stagnant users)
  const since = await getAdvisorEventWindow(userId);
  const [rawEvents, memories] = await Promise.all([
    getRecentEvents(userId, since, purpose === "paths" ? 100 : 40),
    getMemoriesForUser(userId, purpose === "chat" ? 20 : 10),
  ]);

  // Prevent recursive loops by skipping observations produced by Aria itself
  const recentEvents = rawEvents.filter((e) => e.type !== "aria_observation");

  const signals = computeAdvisorSignals(profileInput, recentEvents, memories, activePath);
  const materialChangeDetected = shouldRegeneratePaths(signals);

  return {
    purpose,
    profile: profileInput,
    signals,
    recentEvents: recentEvents.slice(0, purpose === "journal" ? 10 : 15),
    memories: memories.slice(0, 5),
    activePath,
    materialChangeDetected,
  };
}

Cache & Hash Gating (`hashAdvisorContext`)

To optimize performance and minimize LLM expenses, observations are cached in the database (PersistedObservation). The system hashes the AdvisorContext including active memory IDs, event IDs, and skill update timestamps. If the hash matches, the system serves cached observations, bypassing LLM queries entirely.
